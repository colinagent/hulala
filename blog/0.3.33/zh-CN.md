## 想左移一格，回合却停了

会话跑到一半，模型还在写，你想先翻一下会话栏里另一条记录。左手小指按下去：
`Ctrl-[`。屏幕上多了一行 `Turn cancelled`，这一轮就到此为止。

如果你平时用中文输入法，这个动作会更顺手、也更危险。输入法里 `Esc` 是用来取消
候选词的，所以 `Esc` 在你手里是一个"操作键"，不是"发送键"；而 `Ctrl-[` 说的就是
同一件事。在没有键盘协议的终端里，两者是同一个字节：`matchesKey('\x1b', 'escape')`
为真，`matchesKey('\x1b', 'ctrl+[')` 也为真。客户端把 `Esc` 绑成"取消当前回合"，
把 `Ctrl-[` 绑成"焦点左移"，于是每一次按下都同时满足两条规则。

## 一个字节装不下两个动作

第一版修法是让客户端学会区分。请求过键盘消歧协议的终端会把 `Ctrl-[` 报成
`CSI 91;5u`、把 `Esc` 报成 `CSI 27u`，两个事件确实可以分开。这个修正就在 0.3.33 里，
但它自己不够。

不够的原因是"发什么字节"不只由终端决定。输入法可以在终端看到修饰键之前，就把组合键
折叠成一个裸 `0x1b`；Terminal.app 和 iTerm2 则从来不上报键盘协议。在这些会话里，
`Ctrl-[` 无论客户端问过什么，都是 `Esc`。一个键同时意味着"左移"和"中止"，就是那种
只会在你最赶时间的那天踩到的坑。

所以面板键不再落在任何控制字节上。它们落在只属于客户端的组合键上。

## 现在的键位

- `Shift-Cmd-H` / `Shift-Cmd-L`：键盘在会话栏、对话、侧栏之间移动。`Ctrl-Shift-H`
  和 `Ctrl-Shift-L` 是同一组动作的第二写法，给送不到 Command 键的系统用。
- `Shift-Cmd-N` / `Shift-Cmd-P`：在任意焦点位置切到下一个、上一个会话，顺序就是
  会话栏自己的顺序（本目录在前，其余按最近活动排序）。会话栏是显示还是收起都不影响，
  所以每种布局下都是同一个手势。栏内 `Ctrl-N` / `Ctrl-P` 仍然只移动光标：一对切会话，
  一对移高亮。
- `Shift-Cmd-K`：命令面板。它原来是 `Shift-Cmd-P`，把 P 让给了"上一个会话"；而且
  Ghostty 1.4 默认已经把 `super+shift+p` 绑成它自己的命令面板，这个键在本次发版使用的
  终端里原本就是死键。
- `Shift-Cmd-I`：只留 Neovim。它原来是 `Cmd-E`，同样被 Ghostty 1.4 占了
  （`super+e` 是 `search_selection`）。它没有用 `Ctrl-I`：任何 legacy 编码里
  `Ctrl-I` 都是 `Tab` 的 `0x09`，那会把 Tab 从补全菜单、shell 补全和 Neovim 缩进里
  抢走。
- `Esc` 不变：取消正在跑的回合；没有回合在跑时把键盘移进会话栏。焦点在列里时，只要
  列里的程序还有东西可取消（Neovim 除普通模式之外的所有模式、终端列里的全屏程序），
  这个键仍然归程序。

Command 在前、Control 在后是有意的。macOS 上 Command 是主键；Linux 上窗口管理器通常
会先拿走 Super，真正送进终端的是 Control 那一个。`/keys` 两个都印，并且以你自己的
`keybindings.json` 为准。

## 还有哪些做不到

Terminal.app 和 iTerm2 从不把 Command 键交给里面的程序。如果你的终端同时也不上报键盘
协议，`Ctrl-Shift-H` 一个字节都不发，于是是"没有移动键"，而不是"按错了键"。输入框空闲
时 `Esc` 仍会把你送进会话栏，`/rail`、`/editor`、`/terminal` 仍能开关各列，`/keys` 仍是
键位的唯一权威。

你自己的 `keybindings.json` 仍可以把 `ctrl+[` 绑回来。客户端不会拦你，那是你的字节；
只是现在你知道它还是 `Esc`。

另一条限制这次没有、也无法修好：一个键不会告诉你它为什么没到。终端压根不上报键盘协议时，
按下一个 Command 组合，客户端连事件都收不到，自然无法提示。要确认只能看 `/keys`，或者用
调试日志对字节。

## 怎么验证

```sh
hulala update
```

回合运行中按 `Shift-Cmd-H`：键盘进会话栏，回合继续跑。同一个位置按 `Esc`：回合停下，
和以前一样。然后打开 `/keys` 看每组动作的两个写法，`/help` 看周围的规则。

想确认自己的终端到底发了什么，用 `HULALA_DEBUG_CLIENT=1` 启动，按一下键，
`~/.hulala/logs/tui-debug.log` 会写原始字节：`Shift-Cmd-H` 是 `CSI 104;10u`，
`Esc` 是 `CSI 27u`，被终端或输入法折叠过的组合键则是一个裸 `\u001b`。

## 为什么一次把整套键位都改了

这几件事绑在一起。分批发的话，会得到一个 `Shift-Cmd-P` 还开着命令面板、`Shift-Cmd-N`
却在切会话的版本；也会得到一个移动键仍然挂在 `Esc` 字节上的版本。更新日志里是四条记录，
这篇文章是它们背后的同一个理由。
