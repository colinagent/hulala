因为 `/permission` 有两种写法和一句话播报。`Enter` 只改你正在用的这个会话，
只有 `Ctrl-S` 才会连新会话的默认值一起改。0.3.37 让通知说清是哪一种，点名
新对话仍会用的档位，并在列表里把它标出来。

## 我改的到底是哪一个

打开 `/permission`，选「完全权限」，按 `Enter`，模型立刻不再问。下一个对话
又问了。没人骗你，只是那行通知写的是 `permission: Full access`，读起来像一个
设置，而不是一个会话。两者的区别当时只写在同一张列表另一行的 `default` 徽标
上，和一条会滚走的通知里。

现在的通知把两件事一起说，并点名改第二件事的键：

```
permission: Full access for this Session · new Sessions: Workspace Write · Ctrl-S stores it
```

中文界面下是这样：

```
权限：完全权限（仅本会话）· 新会话：工作区内修改 · Ctrl-S 存为默认
```

如果选中的档位本来就是默认值，它不再唠叨，只说一句「新会话相同」。而 `Ctrl-S`
两边都写，就两边都说：`权限：完全权限 · 本会话已切换，并设为新会话默认`。

## 不靠通知怎么确认

现在有两个地方。列表里，新会话会用的那一行在后果说明之前先标出来，窄终端
会先截掉沙箱那句，而不会截掉这一句：

```
 → ✓ 工作区内修改  新会话默认
     完全权限      不再询问 · 不再限制写入
```

`/status` 则把两件事并排成两行，通知滚走之后只剩它还留着这个对照：

```
权限       完全权限
默认权限   工作区内修改
```

`/status` 每次都会问主机，所以就算另一个窗口、web 客户端或 bot 的会话在这期间
改过默认值，它显示的也是当下的值。

## 为什么不让 Enter 直接改默认

因为「这一次放宽」才是常见情况，不是例外。你在某个目录里做一次部署需要完全
权限，但不希望之后每个对话都从无沙箱开始。pi 的选择器本来就是两个手势：`Enter`
为现在选，`Ctrl-S` 顺便把选择存下来。Hulala 保留这个区分，因为它是唯一能表达
「就这一次」的方式。

web 客户端解决同一个问题的办法是分成两个面：设置里那行只写默认值，`/permission`
弹窗只切当前会话，于是没人需要记住一个组合键。终端没有设置页，为了这一行再造
一个平面只会多一个要找的地方。我们保留一个面板，把它的作用说清楚。

## 它拒绝存什么

主机在运行中注册的档位（比如实验性的自动审查）可以用于当前会话，但不能成为
默认值：主机会拿配置表去解析默认值，表外的名字会让之后每一次权限读取和每一次
新建会话都以 `unknown default preset` 失败。0.3.37 之前，在这样的行上按 `Ctrl-S`
会照样写进去，因为设置字段接受任何字符串。

现在它会标成「仅本会话」，`Ctrl-S` 只切会话、不动默认值，并说明原因：

```
权限：自动审查 · 新会话默认未改：Host 不接受它作为新会话默认
```

这和 web 端设置行只提供配置表内选项是同一个保证。

## 这一版还没做什么

它不会改变已经存在的会话。会话在创建时就把档位固定下来了，所以你现在开着的
那些对话会继续按原档位运行，需要各自执行一次 `/permission`；默认值只决定下一个
会话从哪里开始。

它没有在保存「完全权限」默认值之前再加一层确认。我们对照过 web 端：那边两条
路径都有必须勾选的风险确认。终端这边保留原来的答案——选项行说明后果，通知说明
作用域，`/status` 让两者一直可读。把确认框加回来，会让审批弹窗里按 `f` 那条路径
再次成为唯一的例外，而这正是 0.3.36 去掉它的原因。

它也不会把设置变成跨机器的。默认值存在主机上，笔记本和 ssh 过去的机器各有一份，
新会话跟着那台主机的值走。

升级用 `hulala update`，或者从[下载页](/download/)重新安装：

```sh
curl -fsSL https://hulala.ai/install.sh | sh
```

然后打开一次 `/permission`，选「完全权限」，按 `Ctrl-S`。再打开列表看一眼：
「完全权限」那一行上的「新会话默认」，就是下一个对话会从那里开始的凭据。
