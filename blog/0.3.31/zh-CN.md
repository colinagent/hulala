## 标签页就是地址

同时开着五个窗口：一个 shell、一个编辑器，还有三个分别连在三台机器上的会话。切过去，开始打字。如果切错了，不会有任何提示——命令照常执行，只是执行在了你并不想动的那台机器上，你要靠输出去发现。

Hulala 在其他地方对“工作在哪发生”一直很认真：一个状态根、一台机器一个 Host、要换机器就用 `/remote`。唯独窗口标题没有说这件事，所以这个版本从标题开始改。

## 机器在前，目录在后

远程窗口的标签现在以机器开头，写成 `scp` 写远程路径的样子：

```text
root@dev:pi - Hulala:Fix the composer
```

冒号左边是你连上去的 ssh 别名，右边是这个会话工作的目录；产品名后面挂的是 Host 给这个 Session 起的名字。这个版本之前，所有窗口的标题都是 `Hulala - pi - Fix the composer`，本地远程一个样。

顺序是给截断留的。窗口管理器和终端经常只留前二十个字符，所以最能说明“这是哪个窗口”的两件事排在最前面，会话名放最后。本地窗口保持短的那一版，因为目录本身已经说明是本机：

```text
pi - Hulala:Fix the composer
```

在每个本地标签前写 `colin@laptop:` 只是噪音。机器只在不属于本机的时候才出现，而那正是你会弄错的时候。

## 账号是读出来的，不是猜的

标题里写的是你给机器起的别名，不是 ssh 解析出来的地址。账号来自 `ssh -G <alias>`——ssh 自己会用的那份配置，只解析，不连接。

这个细节比看起来重要。给窗口命名不该顺带唤醒一台休眠的机器、不该给标题加网络延迟、也不该让某个从没人连过的主机密钥凭空被信任。别名里没有 `user` 行时，标题仍然可用，写成 `dev:pi`，而不是一个空的 `@`；整条路径都不会碰网络。

## 怎么看到它

更新，然后开一个本地窗口、一个远程窗口：

```sh
hulala update
hulala ssh devbox      # ~/.ssh/config 里你写的别名
```

本地标签显示 `workspace - Hulala`；远程标签显示 `you@devbox:workspace - Hulala`，别名解析不出账号时是 `devbox:workspace - Hulala`。把会话栏收起来，或者切到别的标签再切回来，机器还在标题里——标题不依赖窗口里任何看得见的东西。

## 会话栏为什么让出了一行

会话栏以前单独用一行写机器。那一行本身没错，只是放错了地方：你最需要机器信息的时候，恰恰是没在看会话栏的时候——会话栏收起来了、窗口只是五个里的一个、窗口切换器里只剩四个被截断的标题。终端标签是这三件事都还能看见的唯一位置，而且是每个窗口各自看得见，不是整个应用共用一条。

所以那一行没了，信息没丢：会话栏把那一行还给了会话，机器挪到了操作系统本来就会显示、而且在应用之外也显示的那行文字里。`/remote` 还是能切换已经开着的窗口，`hulala remote <ssh>` 还是能在另一台机器上开窗口，切换时标题也跟着变。

## 归档的提问属于页面本身

以前归档的提问画成一个固定色块。深色主题下它像一张卡片；浅色主题下它就是对话中间的一块深色板子——一个你的终端没有选过、而页面已经选过的颜色。

现在它的底纹是编辑器二级标题的底色：用你自己页面的背景，朝调色板的黄色走十分之一，上面是页面自己的文字色，箭头再淡回底纹里。对话里的提问和编辑器里的 `##` 标题属于同一个色系，因为它们本来就是同一个调色板——而不是两个今天恰好对上的字面量。

有一个边界，而且是刻意留的：这不是客户端自己发明的一套主题，而是从终端真正上报的页面推出来的。终端没有上报页面时，保留原来的固定色块。因为猜一个页面，等于悄悄多出第二套主题；而一个丢了背景色的浅色主题，会被画上加倍的颜色。

## 更新之后可以做什么

还没装的话，[一行命令就能装上 Hulala](/zh-CN/download/)。已经装了，升级完看一眼标签：

```sh
hulala update
```

用浅色主题的话，对话里不会再有那块深色板子。远程窗口的标签会在说别的之前先说清楚机器是哪台，本地窗口则保持干净。不需要配置：这个版本没有新增设置、没有迁移、也没有新的守护进程。

这样的改动其实只值得问一个问题——信息挪去的那个地方，是不是你真正需要它时所在的地方？整个版本就是这一件事：机器挪进了标签，会话栏拿回了它的一行，提问落回了你的页面。
