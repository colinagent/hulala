因为以前后台窗口也能动它。Hulala 在"把按键当命令读"的表面拿到键盘时会切 macOS
的输入源，而它根本没有办法知道自己是不是在前台。0.3.38 读终端的焦点报告，窗口在
后台时就一个字节都不碰键盘。

## 到底是谁在切

你在别的窗口打中文，跑 Hulala 的终端在它后面，上面挂着一张没人回答的审批卡。输入
法突然跳成 ABC，过几分钟它被重新选中时，又弹一条"快捷键冲突"的提示。

那不是快捷键冲突。是客户端请系统选了一个布局，而那个时刻窗口并不在你正在打字的
地方。系统日志里能看到 helper 是从客户端进程里起来的，而客户端完全不知道自己的窗口
在别人后面。

## 为什么它不可能知道

终端里的程序只看得见 pty 里的字节。窗口被切到别的应用后面这件事，只有当终端告诉它
时才知道，这就是焦点报告（`DEC ?1004`）：窗口获得焦点时发 `ESC [ I`，失去焦点时发
`ESC [ O`。

这个模式原来是我们**故意关掉**的——每条报告都是一个可能被读取边界切开、然后被当成
文字打进 composer 的序列。关掉它，垃圾没有了，信息也没有了。要拿回信息，就得同时
拿回"这些字节绝不可能是输入"这个保证。

## 改了什么

焦点报告现在有了主人。客户端自己的终端包装在字节到达时认出 `ESC [ I` / `ESC [ O`，
记下状态，然后**照常交给屏幕**——屏幕照旧把它们消费掉。没有任何新的东西能被打成
文字，因为没有任何新的东西到达 composer。

输入源的所有权在做任何事之前先看这个状态：

- 窗口在前台、命令表面持有键盘：切到一个键盘布局，和以前一样；
- 窗口失焦：**立刻**把用户自己的输入源还回去，而不是扣到那个表面消失为止；
- 窗口在后台时策略发生变化：**一次调用都不发**。

最后一条就是开头那个故事的修复：一张出现在没人看的窗口里的审批卡，不再选中任何东西。

不支持焦点报告的终端保持原来的行为——客户端当自己在前面，和这个版本之前完全一致。

## 测试也不再碰你的键盘

同一个问题的另一半是我们自己造成的。e2e 套件会在真 pty 上用临时状态根启动**真客户端**，
那个客户端把输入源 helper 发布进临时根，然后真的用它。一次 `bun run test` 在 macOS 上
7 秒里选中了 21 次真实系统输入源。如果你在写测试的时候跑它，你的键盘就是测试夹具。

现在临时状态根就是"自动化运行"：永不持有输入源；其它 harness 可以用
`HULALA_INPUT_SOURCE=0/1` 显式说明。同一套件现在选中 0 次。

## 它切到哪一个

helper 是**问 macOS** 要一个键盘布局，优先挑声明语言含英文的那个。没有写死任何厂商
或布局 id：第三方的英文布局一样能用，删掉 ABC 和 US 的机器也仍然找得到一个布局，
而不是切到空。

英文只是偏好，不是判据。任何键盘布局都只产出字符、不组字，这才是命令表面需要的性质；
别的布局会挪动标点和 `y`/`z`，对 vim 动作更糟。**还回去**是另一套机制：客户端记住
系统在切换前报告的那个 id——豆包、搜狗、Apple 拼音都行——并在确认"还是我们改的那个"
之后，原样把它选回去。

## 仍然会发生的事

前台窗口里的命令表面**仍然会**切到布局。这就是这个功能本身：在 Neovim normal、侧栏、
选择器、审批卡里，中文输入法会把 `j`、`Enter`、`Esc` 吃成组字串。输入法的语音键也只在
它自己是当前输入法时才可用，所以强制布局的命令表面不是用语音的地方。

这个版本里还有两件小事。页脚不再在模型后面追加会话的权限档位——那是配置，归
`/permission` 和 `/status` 管，不该混在一行运行数据里。另外，工具结果里的图片在任何
一部分还在视野内时都会继续画，滚动不会再把它整张带走。

升级用 `hulala update`，或者从[下载页](/download/)安装。
