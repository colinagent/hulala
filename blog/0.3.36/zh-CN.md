终端里只看到一行字、看不到图片，原因是工具返回的是引用而不是像素，而 Hulala
把引用原样打了出来。0.3.36 向主机要回字节，把图片画在工具行下面；主机在远端的
机器上时也一样。

## 那一行字

你贴一张截图，或者让模型打开某个图片文件，它对图里的内容答得头头是道，可对话
里只有这么一行：

```
[Image: shot.png [image/png] 800x600]
```

哪一步都没出错。`read_image` 把文件提交到主机的附件存储，返回的是一个引用：小、
持久、指向拥有这个 Session 的那台机器上的一个对象。客户端画完引用就停住了。像素
从读的那一刻起就在主机上，只是没有人去要。

## 现在的工具行

带图片的工具结果会把图画在自己的行下面。终端支持 Kitty 图形协议时（Ghostty、
kitty、WezTerm、Warp），像素直接放进画面：结果里的二维码就是能拿手机扫的二维码，
截图按它原本的尺寸显示出来。

字节走的是 Session 自己的附件通道，所以主机在别的机器上和在本机上是同一件事。这
一点值得说清楚：过线的东西只有这张图，你面前这个窗口没有读过任何文件。

每张附件只取一次。同一张图出现在两个工具行里，只摆放一次；对话保留已经画出的行，
往回滚动不会让某一行重新向主机要它早就有的字节。

Kitty 只传 PNG，所以 JPEG、WebP、GIF 会先转码。转换器是一兆左右的 WebAssembly，
在第一张非 PNG 图片出现时才加载，而不是启动时加载；顺手把照片的 EXIF 方向应用上，
否则手机竖着拍的图会躺着显示。一个结果最多占 60 列、30 行，太长的手机截图会被缩进
这个框，而不是把整轮对话顶出屏幕。

不支持图形协议的终端仍然只有那行引用，客户端根本不会去要字节。这是少下载一兆，
不是画面退化：`[Image: photo.jpg [image/jpeg] 800x600]` 照样说明有什么、从哪来。

## 点开对话里的链接

这次另一半改动是对话里指出的另一类东西：目标。规则是链接由拥有它的那台机器打开，
而不是由刚好在画这一帧的机器打开。Hulala 是两个进程，它们只是有时候在同一台电脑上。

所以 URL 交给你面前的浏览器。它跟位置无关，远端那台机器没有浏览器，`https://` 在
ssh 的两端指的是同一个东西。

路径交给主机。主机拿它和 Session 的目录比对、限制在工作区之内，然后把找到的绝对
路径回给客户端，编辑器列打开这个路径——列里的 Neovim 本身就是主机上的程序，所以
整个解析只有一次。链接目标写成裸文件名也能用，原因就在这里：
`[笔记](2026-11-24-trader-trade-memory.md)` 是在 Session 旁边解析，不是在窗口旁边。

失败会说出口，而不是点了没反应。解析不到的目标给出
`can't open notes.md: <主机给的原因>`，浏览器起不来也有自己的一条提示。

## 还有哪些做不到

Terminal.app 和 iTerm2 仍然只显示引用。备用屏只为 Kitty 协议保留摆放位置，一个
假装画了图的降级比一个说出文件名的降级更糟。

工作区之外的路径会被主机拒掉，这跟文件工具一直以来的边界是同一道。图片也只在工具
结果里画，正文里提到的图仍然只是一个链接。

0.3.36 剩下的部分安静一些：每个面板都有一个循环键（`Ctrl-D` 会话栏、`Ctrl-F`
对话、`Ctrl-T` 终端、`Ctrl-G` Neovim），`/permission` 变成一个选择器，`Enter`
切换本 Session、`Ctrl-S` 同时存成新 Session 的默认值，审批理由会换行，而不是在
对话框边缘以 `…` 结束。

用 [安装 Hulala](/download/) 或 `hulala update` 拿到它；上一版讲的是
[面板快捷键怎么从 Command 组合键上搬走](/zh-CN/blog/panel-keys-without-a-command-key/)。
